# AI Lab 信息搜集与需求洞察 Agent
# 低保真原型框架 + 页面模块说明 v1.0

> 文档用途：用于一期原型设计、前端页面拆分、评审沟通与后续 UI 生成。  
> 设计参考：参考 AIHOT 的左侧导航、精选信息流、全部动态、日报、信源提报、更新日志等结构，但结合 AI Lab 一期 PRD 重新组织为“信息 → 日报 → 洞察 → 策略输出”的工作流。  
> 一期核心范围：信息源管理、全部信息动态、精选情报、日报、需求洞察工作台、洞察结果、策略输出、反馈与更新日志。  
> 一期暂不做：复杂权限、外部 Agent 接入、公众号 / App Store / 小红书 / B 站采集、大规模全网爬虫、完整项目机会池状态流转。

# 1. 精选情报页

## 页面名称

精选情报

## 页面目标

展示系统从全部信息动态中自动筛选出的高价值内容。该页不展示所有信息，只展示“值得继续看、值得生成洞察、值得进入策略判断”的内容。

## 低保真原型框架

```text
┌────────────────────────────────────────────────────────────────────┐
│ 精选                                                               │
│ AI 自动筛选的高价值内容                                             │
├────────────────────────────────────────────────────────────────────┤
│ [全部] [AI Agent] [产品] [行业] [开源/工程] [本地生活] [即时配送]    │
│                                            [搜索标题/摘要...] [搜索] │
└────────────────────────────────────────────────────────────────────┘

5月18日

10:45  ●  ┌──────────────────────────────────────────────────────┐
          │ 来源：IT之家 / RSS                         [精选] [70] │
          │ 标题：腾讯 AI 设计智能体 Ardot 公测                     │
          │ 摘要：一句话生成可编辑设计稿，一键转代码...              │
          │ 标签：[智能体] [MCP/工具] [产品更新]                    │
          │ 推荐理由：可作为 AI Lab 内部设计提效工具参考             │
          │ 相关场景：设计资产 AI 化 / 工程效率 / 内部提效           │
          │ 操作：[查看详情] [生成洞察] [暂不跟进]                  │
          └──────────────────────────────────────────────────────┘

10:35  ●  ┌──────────────────────────────────────────────────────┐
          │ 来源：Product Hunt                         [精选] [64] │
          │ 标题：某视频工具支持模版化生成短视频                    │
          │ 摘要：用户上传素材后自动生成视频...                     │
          │ 标签：[多模态] [内容生成] [产品更新]                    │
          │ 推荐理由：可参考商户素材生成、运营素材生产场景           │
          │ 操作：[查看详情] [生成洞察] [暂不跟进]                  │
          └──────────────────────────────────────────────────────┘
```

## 页面模块说明

| 模块 | 说明 |
|---|---|
| 页面标题区 | 展示“精选”和说明文案，说明该页为 AI 自动筛选的高价值内容 |
| 分类筛选区 | 支持按内容方向筛选，例如 AI Agent、产品、行业、开源/工程、本地生活、即时配送 |
| 搜索区 | 支持按标题、摘要、来源、标签搜索 |
| 日期分组 | 按日期组织精选内容，降低信息流浏览压力 |
| 时间线 | 参考 AIHOT 的时间线结构，展示内容发布时间或采集时间 |
| 精选信息卡 | 展示来源、标题、摘要、标签、推荐理由、相关场景、价值分 |
| 操作区 | 支持查看详情、生成洞察、暂不跟进 |

## 卡片字段

| 字段 | 说明 |
|---|---|
| 来源 | 信息来源名称，例如 IT之家、Product Hunt、GitHub、官方博客 |
| 来源类型 | RSS、官网、GitHub、研报、用户上传等 |
| 标题 | 原始信息标题 |
| 摘要 | AI 生成 2-3 句摘要 |
| 推荐理由 | 为什么值得 AI Lab 关注 |
| 相关场景 | 用户侧、跑男侧、商户侧、客服侧、运营侧、内部提效 |
| 标签 | AI Agent、Workflow、多模态、工程效率、竞品动作等 |
| 价值分 | 0-100，表示继续分析价值 |
| 状态 | 未读、已读、已生成洞察、暂不跟进 |
| 操作 | 查看详情、生成洞察、暂不跟进 |

## 关键交互

1. 点击分类标签，刷新列表。
2. 点击“生成洞察”，进入需求洞察工作台，并带入该条信息。
3. 点击“暂不跟进”，该内容从精选页移除，但保留在全部信息动态。
4. 点击信息卡片，右侧弹出信息详情抽屉。

## 异常状态

| 场景 | 处理 |
|---|---|
| 当天没有精选内容 | 展示空状态：“今日暂无高价值情报，可前往全部动态查看。” |
| 内容摘要生成失败 | 展示原始摘要，并标记“待重新生成” |
| 价值分过低 | 不进入精选，只留在全部动态 |
| 来源失效 | 卡片标记“来源异常”，不允许生成洞察 |

## 页面模块说明

| 模块 | 说明 |
|---|---|
| 页面标题区 | 展示“全部信息动态”和说明文案 |
| 来源类型筛选 | 按官网、RSS、GitHub、Hugging Face、研报、用户上传等筛选 |
| 内容方向筛选 | 按 AI Agent、产品、行业、开源/工程、本地生活等筛选 |
| 状态筛选 | 全部、未读、已读、已生成洞察、暂不跟进 |
| 搜索区 | 按标题、摘要、来源、标签搜索 |
| 信息时间线 | 按日期和时间展示全部动态 |
| 信息卡片 | 展示标题、摘要、来源、标签、状态、价值分 |
| 操作区 | 查看详情、生成洞察、加入精选、忽略 |

## 列表字段

| 字段 | 说明 |
|---|---|
| 发布时间 | 原文发布时间或系统采集时间 |
| 来源名称 | 信息源名称 |
| 来源类型 | 官网、RSS、GitHub、研报、用户上传等 |
| 标题 | 原始标题 |
| 摘要 | AI 摘要 |
| 标签 | 自动标签 |
| 价值分 | 初筛分数 |
| 状态 | 未读、已读、已生成洞察、暂不跟进 |
| 操作 | 查看、生成洞察、加入精选、忽略 |

## 关键交互

1. 用户可以通过筛选器快速缩小内容范围。
2. 点击“加入精选”后，信息进入精选情报页。
3. 点击“生成洞察”后，进入需求洞察工作台。
4. 点击“忽略”后，状态变为暂不跟进。
5. 点击信息卡片，打开右侧详情抽屉。

## 异常状态

| 场景 | 处理 |
|---|---|
| 无筛选结果 | 展示空状态，并提供“重置筛选”按钮 |
| 来源重复 | 合并为同一事件，保留多来源 |
| 内容抓取失败 | 展示标题和来源，正文处显示“正文解析失败，可手动补充” |
| 内容过期 | 标记“已过期”，不进入精选推荐 |

# 3. AI 日报页

## 页面名称

AI 日报

## 页面目标

按日期沉淀每日信息汇总，让 AI Lab 快速了解当天重点变化。日报不是策略结论，而是信息汇总入口；后续可从日报中的条目继续进入洞察分析。

## 低保真原型框架

```text
┌──────────────────┐ ┌──────────────────────────────────────────────┐
│ 最新一期          │ │ AI Lab 日报                                  │
│ 2026-05-18       │ │ 2026年5月18日  星期一                         │
├──────────────────┤ ├──────────────────────────────────────────────┤
│ 2026年5月         │ │ 01 产品发布 / 更新                 3 篇        │
│ 18日  当前选中    │ │ ┌──────────────────────────────────────────┐ │
│ 17日              │ │ │ Grok Imagine 图像生成功能正式发布          │ │
│ 16日              │ │ │ 摘要：...                                  │ │
│ 15日              │ │ │ 操作：[查看信息] [生成洞察]                 │ │
│ 14日              │ │ └──────────────────────────────────────────┘ │
│ ...              │ │ ┌──────────────────────────────────────────┐ │
│                  │ │ │ 手机端 ChatGPT 应用集成 Codex 构建功能     │ │
│                  │ │ └──────────────────────────────────────────┘ │
│                  │ │                                              │
│                  │ │ 02 开源 / 工程                    4 篇        │
│                  │ │ 03 行业动态                       2 篇        │
│                  │ │ 04 值得进入洞察                    3 条        │
└──────────────────┘ └──────────────────────────────────────────────┘
```

## 页面模块说明

| 模块 | 说明 |
|---|---|
| 左侧日期导航 | 展示最近日报列表，支持按月分组 |
| 日报标题区 | 展示日期、星期、当日条数 |
| 分类内容区 | 按产品发布/更新、开源/工程、行业动态、值得进入洞察等分组 |
| 日报条目 | 展示标题、来源、摘要、标签 |
| 推荐洞察区 | 列出系统认为值得进一步洞察的内容 |
| 操作区 | 查看信息、生成洞察、加入精选、导出日报 |

## 日报分类建议

| 分类 | 说明 |
|---|---|
| 产品发布 / 更新 | AI 产品、工具、竞品新功能 |
| 开源 / 工程 | GitHub、Hugging Face、开发者工作流 |
| 行业动态 | 行业媒体、公司动作、趋势变化 |
| 研究 / 研报 | 研究报告、论文、模型趋势 |
| 值得进入洞察 | 当日最值得继续分析的内容 |
| 和 UU 相关 | 映射到 UU 业务场景的信息 |

## 关键交互

1. 点击左侧日期切换日报。
2. 点击日报条目打开信息详情。
3. 点击“生成洞察”，进入需求洞察工作台。
4. 点击“导出日报”，导出 Markdown / 飞书文档格式。
5. 支持在日报顶部显示“今日推荐关注”。

## 异常状态

| 场景 | 处理 |
|---|---|
| 当天无内容 | 显示“今日暂无采集内容” |
| 某分类无内容 | 隐藏该分类或展示空占位 |
| 日报生成失败 | 保留原始信息列表，提示重新生成 |
| 日报内容过多 | 默认折叠分类，显示每类前 3 条 |

# 4. 信息源管理页

## 页面名称

信息源管理

## 页面目标

管理一期白名单信源，包括来源类型、优先级、抓取方式、启用状态、最近抓取时间。该页服务后台配置和 AI Lab 成员协作维护，不面向普通浏览。

## 低保真原型框架

```text
┌────────────────────────────────────────────────────────────────────┐
│ 信息源管理                                                         │
│ 维护一期白名单信源，确保输入质量稳定                                │
├────────────────────────────────────────────────────────────────────┤
│ [新增信源] [批量导入] [检查失效源]                                  │
│ 类型：[全部] [竞品官网] [行业媒体] [GitHub] [Hugging Face] [研报]     │
│ 优先级：[全部] [P0] [P1] [P2]   状态：[启用] [停用] [失效]           │
└────────────────────────────────────────────────────────────────────┘

┌──────┬──────────────┬──────────┬──────┬────────┬────────┬────────┐
│优先级│ 信源名称       │ 类型       │难度 │抓取方式 │最近抓取 │状态     │
├──────┼──────────────┼──────────┼──────┼────────┼────────┼────────┤
│ P0   │ Product Hunt │ 产品洞察   │ 中   │ RSS    │ 今日    │ 启用     │
│ P0   │ GitHub Blog  │ 开源工程   │ 低   │ RSS    │ 今日    │ 启用     │
│ P1   │ 少数派        │ 产品洞察   │ 低   │ RSS    │ 昨日    │ 启用     │
│ P2   │ a16z AI      │ 创业生态   │ 高   │ 页面抓取│ 3天前   │ 观察中   │
└──────┴──────────────┴──────────┴──────┴────────┴────────┴────────┘
```

## 页面模块说明

| 模块 | 说明 |
|---|---|
| 页面标题区 | 说明信息源管理目的 |
| 操作区 | 新增信源、批量导入、检查失效源 |
| 筛选区 | 按类型、优先级、状态筛选 |
| 信源表格 | 展示所有白名单信源 |
| 信源详情抽屉 | 查看信源配置、抓取规则、历史产出 |
| 质量评估区 | 展示该信源有效洞察数、低价值率、失败次数 |

## 表格字段

| 字段 | 说明 |
|---|---|
| 优先级 | P0/P1/P2 |
| 信源名称 | 网站、平台、博客、仓库名称 |
| 链接 | URL |
| 类型 | 竞品官网、行业媒体、GitHub、Hugging Face、研报等 |
| 抓取难度 | 低/中/高 |
| 抓取方式 | RSS、页面抓取、GitHub Releases、人工上传 |
| 最近抓取 | 最近采集时间 |
| 产出洞察数 | 该信源产生的有效洞察数量 |
| 状态 | 启用、停用、失效、观察中 |
| 操作 | 编辑、停用、查看记录、测试抓取 |

## 关键交互

1. 新增信源时先判断是否在一期白名单范围。
2. 信源测试抓取成功后才能启用。
3. 连续低价值或失败的信源自动提示降级。
4. 点击信源可查看历史抓取记录和洞察贡献。

## 异常状态

| 场景 | 处理 |
|---|---|
| 信源不在一期范围 | 提示“当前版本暂不支持该来源类型” |
| RSS 失效 | 标记失效，提示手动检查 |
| 抓取失败 | 记录失败次数，超过阈值停用 |
| 重复信源 | 合并到已有信源，不重复入库 |

# 5. 信源提报页

## 页面名称

信源提报

## 页面目标

让 AI Lab 成员主动提交优质信息源，并形成“信源墙”，增加共建感。参考 AIHOT 的信源提报结构，但只接收一期范围内的信源类型。

## 低保真原型框架

```text
┌────────────────────────────────────────────────────────────────────┐
│ 信源提报                                                           │
```

| 操作区 | 加入实验池、查看实验复盘、标记暂缓 |

## 策略卡字段

| 字段 | 说明 |
|---|---|
| 策略标题 | 一句话描述行动方向 |
| 优先级标签 | 优先策略、值得观察、暂不跟进 |
| 价值分 | 0-100 |
| 目标场景 | 用户侧、跑男侧、客服侧、商户侧、运营侧、内部提效 |
| 能力标签 | Agent、Workflow、多模态、评测、知识库、自动化 |
| UU 跑腿价值 | 对 UU 业务的作用 |
| AI Lab 价值 | 对 AI Lab 能力沉淀的作用 |
| 建议动作 | 建议先做什么 |
| 来源动态 | 来自哪条信息或洞察 |
| 负责人建议 | 推荐跟进方 |
| 操作 | 加入实验池、查看复盘、暂缓 |

## 关键交互

1. 用户可按优先级、业务线、能力标签筛选策略。
2. 点击策略卡进入策略详情。
3. 点击“加入实验池”进入后续承接位，v1.1 做完整状态流转。
4. 点击“查看实验复盘”查看已有验证记录。
5. 点击“标记暂缓”后策略进入暂缓列表。

## 异常状态

| 场景 | 处理 |
|---|---|
| 洞察未确认 | 不允许生成优先策略，只能生成“待确认策略” |
| 缺少建议动作 | 不允许发布到策略输出页 |
| 价值分低于阈值 | 进入“值得观察”或“暂不跟进” |
| 负责人无法判断 | 标记“待分配负责人” |

# 14. 原型设计注意事项

## 14.1 视觉和结构参考

1. 左侧固定导航，参考 AIHOT 的轻量信息工具结构。
2. 精选情报和全部动态使用时间线 + 卡片结构。
3. 日报页面使用左侧日期列表 + 右侧日报内容。
4. 信源提报使用表单 + 信源墙。
5. 更新日志使用日期时间线。
6. 策略输出使用深色或高对比卡片，突出“行动建议”和“价值分”。

## 14.2 一期不要复杂化

不要在一期做以下内容：

```text
复杂权限系统
外部 Agent 接入
全网爬虫
多角色个性化首页
复杂大屏
项目机会池完整状态流转
实验复盘闭环
公众号 / App Store / 小红书 / B站自动采集
```

## 14.3 低保真目标

一期低保真只需要验证：

```text
信息能否稳定进入系统
用户能否从精选/日报快速看到重点
用户能否把信息转成洞察
洞察结果能否结构化沉淀
策略输出是否能回答“下一步怎么做”
```
